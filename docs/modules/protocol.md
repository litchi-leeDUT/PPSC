# Protocol 模块约定

> 状态：草案，可直接修改。对应 crate：`ppsc-protocol`

## 职责

- 定义任务协议状态机、轮次消息和对外动作。
- 调用 `CryptoProvider`，但不接触套接字、gRPC、数据库或链 RPC。
- 编排 sortition、程序装载、跨委员会 handoff 和 Sharing/HE gateway。

详细协议见 [密态智能合约与动态混合协议](../confidential-contract-protocol.md)。

## 必须遵守

- 相同输入、状态和密码结果必须产生相同动作。
- 每条消息验证任务、版本、委员会成员、轮次和防重放 ID。
- 状态更新与消息持久化的顺序必须支持崩溃恢复。
- 超时/重试由显式事件驱动，协议内部不得依赖隐式系统时钟。

## 接口契约

- `initialize` 对同一已初始化任务必须幂等或明确拒绝。
- `handle_message` 不得在验证完成前执行密码操作。
- `resume` 必须校验 checkpoint 的版本和完整性。
- 动作只描述意图，由节点编排层执行副作用。

## 测试清单

- 每个状态和轮次的表驱动测试。
- 消息乱序、重复、缺失、恶意发送者和版本不兼容。
- 任意动作后崩溃并恢复。
- 多节点确定性模拟测试。
